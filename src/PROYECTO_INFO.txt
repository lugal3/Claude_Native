INFORME DE PROYECTO: Pedidos360 (Tienda 'amirgo')

1. RESUMEN DEL PROYECTO
- Nombre en código: Pedidos360 (Frontend de simulación: Tienda de Arte Minimalista 'amirgo').
- Stack Tecnológico: React 18 (JavaScript puro, SIN TypeScript), Vite, CSS puro, React Router DOM v6.
- Objetivo Principal: Proveer un frontend público y un dashboard privado protegido por autenticación y consumir un backend alojado en AWS API Gateway.

2. ARQUITECTURA DE AUTENTICACIÓN (IDaaS)
- Proveedor: Microsoft Entra ID (Azure AD).
- Librerías: @azure/msal-browser y @azure/msal-react.
- Flujo: Authorization Code con PKCE.
- Configuración Centralizada: Ubicada en `src/config/authConfig.js`. Requiere inyectar CLIENT_ID, TENANT_ID, REDIRECT_URI de la App registrada en Azure.

3. ESTRUCTURA Y COMPONENTES CLAVE
- `src/main.jsx`: Punto de entrada. Inicializa la instancia `PublicClientApplication` de MSAL y envuelve la app en `<MsalProvider>`. Redirige al usuario logueado.
- `src/App.jsx`: Gestor de rutas usando `react-router-dom`. Define `/` (Pública) y `/dashboard` (Privada).
- `src/components/ProtectedRoute.jsx`: Componente "Guard". Redirige a `/` si el usuario no tiene una sesión activa en MSAL.
- `src/pages/Home.jsx`: Vista pública de la tienda amirgo. Contiene el diseño minimalista en tono hueso y el botón para disparar `loginRedirect` de MSAL.
- `src/pages/Dashboard.jsx`: Vista privada. Muestra los claims del ID Token de Azure (ej. roles del usuario) y consume datos del backend de AWS.

4. COMUNICACIÓN CON EL BACKEND (AWS API Gateway)
- `src/hooks/useApi.js`: Custom hook que envuelve el método `acquireTokenSilent` de MSAL para obtener el Access Token en crudo, y hace fallback a `acquireTokenRedirect` en caso de error/expiración.
- `src/services/api.js`: Utiliza `axios` para configurar el cliente HTTP. Exporta funciones como `getObras(token)` que inyectan el JWT en el header `Authorization: Bearer <token>`.
- Configuración AWS: Se asume que el backend en AWS API Gateway tiene configurado CORS habilitado y un JWT Authorizer validando el Issuer (Azure Entra ID) y el Audience (App de React o App Intermedia de backend).

5. ESTILOS
- `src/index.css`: Contiene todo el CSS puro del proyecto. Utiliza variables CSS y una paleta de colores limpia (fondo hueso: #f9f6f0, texto oscuro: #2c2c2c) priorizando el minimalismo.

6. PASOS SIGUIENTES PARA DESARROLLO
- Rellenar el `authConfig.js` con las IDs correctas de Azure.
- Asegurar que la URL del frontend esté en las "Redirect URIs" permitidas de la App de Entra ID como SPA.
- Ajustar `apiConfig.protectedResourceScopes` según el Expose API de Azure (si el backend requiere tokens de acceso específicos en vez de un simple ID token).
- Manejar los CORS en AWS de forma estricta (permitir el origen de React y el header 'Authorization').
